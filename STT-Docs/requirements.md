# KoeNote（コエノート）— 要件定義書

**バージョン**: 1.2  
**作成日**: 2026-04-18  
**ステータス**: ドラフト改定版

---

## 1. サービス概要

### 1.1 背景・目的

学校の講義、企業セミナー、説明会などでは、口頭説明と配布資料が同時に存在する。利用者はその場では「聞くこと」に集中したい一方、終了後には内容を正確に振り返り、必要なアクションをすぐ実行できる状態が求められる。

既存の文字起こしアプリはリアルタイム表示を主価値に置くものが多いが、以下の課題が残る。

- 専門用語、固有名詞、数字の誤認識が多く、後編集コストが高い
- 配布資料を踏まえた補正が弱く、講義や説明会の文脈に追随しづらい
- 文字起こし後の要約、整理、Todo化が分断されている

KoeNote は、**長時間録音を確実に残し、録音後に高精度なノートへ変換すること** を中核価値とする。MVPでは、リアルタイム表示の豪華さよりも、録音完了後に「読み返せる品質のノート」が得られることを優先する。

### 1.2 サービス名

**KoeNote（コエノート）**  
声（Koe）＋ Note（ノート）。声がそのままノートになるコンセプトを表す。

### 1.3 対応プラットフォーム

| フェーズ | プラットフォーム |
|----------|-----------------|
| MVP（Phase 1） | iPhone（iOS 17以上） |
| Phase 2以降 | iPad対応 |
| 将来構想 | Android / Web対応を検討 |

### 1.4 プロダクト方針

- MVPの主価値は「録音後の高精度ノート化」
- 録音後の文字起こしはクラウドASR（Whisper API）を標準とし、高精度を優先する
- リアルタイム文字起こしはオンデバイスASRによるプレビュー専用とし、MVPの成功条件から外す
- AI利用料金はサービス提供者が負担する
- ユーザーに外部APIキー入力を要求しない
- APIキーはバックエンドプロキシで管理し、アプリ内には埋め込まない
- Phase 1 はローカル利用を前提とし、ログインやチーム共有は対象外とする

## 3. MVP成功条件

### 3.1 MVPで解く課題

- 長時間の音声を取りこぼさず記録できる
- 録音後に、読み返し可能な品質の文字起こしが得られる
- 配布資料を加味して、専門用語・固有名詞の誤認識を減らせる
- 要点整理までが1セッション内で完結する

### 3.2 MVP成功指標

| 指標 | 目標値 |
|------|--------|
| 録音完了率 | 95%以上 |
| ノート生成成功率 | 90%以上 |
| 補正後テキスト満足度 | 5段階評価で平均4.0以上 |
| 補正後WER改善率（資料あり） | 補正前比で30%以上改善 |
| 補正後WER改善率（資料なし） | 補正前比で20%以上改善 |
| 要約生成利用率 | 録音完了セッションの60%以上 |

## 4. 機能要件

### Phase 1 — MVP（録音後の高精度ノート化）

---

#### 機能1：セッション録音

**ユーザーストーリー**  
> As a ユーザー,  
> I want to 迷わず録音を開始して最後まで保存できる,  
> So that その場では内容を聞くことに集中できる。

**受け入れ条件**
- [ ] ホーム画面から1タップで新規録音を開始できる
- [ ] 録音中は録音状態、経過時間、入力レベルが確認できる
- [ ] 録音停止後、音声ファイルがセッションとして自動保存される
- [ ] セッション一覧から過去の録音に再アクセスできる
- [ ] 録音失敗時は原因が表示され、再試行できる
- [ ] 60分以上の録音データを保存できる

**MVPでの扱い**
- リアルタイム文字起こしは必須ではない
- 画面オフ中の録音継続は必須要件とする
- 録音中の文字起こし品質は成功判定に含めない

---

#### 機能2：録音後文字起こし

**ユーザーストーリー**  
> As a ユーザー,  
> I want to 録音終了後に音声が高精度で文字起こしされる,  
> So that 自分で聞き直さなくても内容を読み返せる。

**受け入れ条件**
- [ ] 録音停止後、自動で文字起こしジョブを開始できる
- [ ] 文字起こし中は進行状態が表示される
- [ ] 完了後、セッション詳細画面で全文を閲覧できる
- [ ] 文字起こし結果をコピーできる
- [ ] 文字起こし失敗時は再実行できる
- [ ] 文字起こしはクラウドASRを標準利用し、長時間音声を対象にできる

**制約**
- 録音後の文字起こしはクラウドASR（Whisper API）を標準とし、長時間音声に対応する
- リアルタイム文字起こしはオンデバイスASR（SFSpeechRecognizer）によるプレビューとし、品質は問わない
- オフライン時は録音保存のみ行い、文字起こしは保留状態にする
- ネットワーク復帰後に保留中の文字起こしジョブを自動再実行できる

---

#### 機能3：資料スキャンとOCR

**ユーザーストーリー**  
> As a ユーザー,  
> I want to 配布資料をセッションに追加できる,  
> So that 専門用語や固有名詞をノート生成時に反映できる。

**受け入れ条件**
- [ ] セッション開始前または録音後に資料スキャンを追加できる
- [ ] 複数ページのスキャンに対応する
- [ ] OCR結果をセッションに保存できる
- [ ] スキャン画像とOCRテキストを確認できる
- [ ] 不要な資料ページを削除できる

**制約**
- OCR結果は全文をそのまま投入せず、後続処理で利用しやすい形に整形できること
- Phase 1 では最大20ページを上限とする

---

#### 機能4：AI補正

**ユーザーストーリー**  
> As a ユーザー,  
> I want to 文字起こし結果が資料文脈を踏まえて補正される,  
> So that 専門用語や固有名詞の誤認識を減らせる。

**受け入れ条件**
- [ ] 文字起こし完了後、補正ジョブを自動実行できる
- [ ] 補正前テキストと補正後テキストを切り替えて閲覧できる
- [ ] ユーザーは補正後テキストを手動編集できる
- [ ] 補正失敗時は補正前テキストをそのまま利用できる
- [ ] 資料が存在する場合、補正処理で資料由来の用語情報を利用できる

**制約**
- 差分ハイライト表示や「修正箇所単位で元に戻す」は Phase 1 対象外
- 補正は意味改変よりも誤認識修正を優先する
- 補正対象は全文でも、内部的にはトークン上限を考慮して分割処理できること

---

#### 機能5：ノート生成

**ユーザーストーリー**  
> As a ユーザー,  
> I want to 文字起こしから読みやすいノートを生成したい,  
> So that 終了後すぐに要点を振り返れる。

**受け入れ条件**
- [ ] 補正後テキストからノート生成を実行できる
- [ ] ノート形式は少なくとも「学習ノート」「議事メモ」の2種類を選択できる
- [ ] ノートはMarkdown形式で保存される
- [ ] ノート内容をアプリ内で編集できる
- [ ] ノートをテキストとして共有またはエクスポートできる

**制約**
- ノート生成は録音後の主価値機能として Phase 1 に含める
- 資料がある場合はノート生成にも反映する

## 5. 非機能要件

### 5.1 パフォーマンス

| 指標 | 目標値 |
|------|--------|
| 録音開始時間 | ボタン押下から3秒以内 |
| 文字起こし完了時間 | 60分音声で10分以内 |
| AI補正完了時間 | 文字起こし完了後3分以内 |
| ノート生成時間 | 補正完了後60秒以内 |
| ドキュメントOCR処理時間 | 1ページあたり5秒以内 |
| アプリ起動時間 | コールドスタートで3秒以内 |

### 5.2 品質

- 長時間音声を優先ユースケースとする
- 補正後テキストは、最低でも「読み返して理解できる」品質を満たす
- 専門用語や固有名詞は、資料未使用時より資料使用時のほうが精度改善すること

### 5.3 セキュリティ・プライバシー

- 音声、文字起こし、資料画像は端末内に保存する
- 保存データはOS標準のデータ保護機構を利用して保護する
- クラウド処理に必要なデータのみ送信する
- AI APIキー・ASR APIキーはバックエンドプロキシで管理し、アプリ内に埋め込まない
- バックエンドプロキシでデバイス単位のレート制限・コスト上限を制御する
- 音声ファイルはASR API以外には送信しない（AI補正にはテキストのみ送信）

### 5.4 可用性・オフライン対応

- オフライン時でも録音とローカル保存は可能
- オフライン時は文字起こし、補正、ノート生成を保留状態にできる
- ネットワーク復帰後に保留ジョブを再実行できる

### 5.5 アクセシビリティ

- Dynamic Type対応
- VoiceOver対応
- ダークモード対応

### 5.6 対応デバイス

- iPhone（iOS 17.0以上）
- iPad対応は Phase 2

### 5.7 ストレージ・バッテリー

- 60分録音のストレージ使用量は50MB以下を目標とする
- 60分連続録音時のバッテリー消費は10%以下を目標とする
- 端末容量不足時は録音開始前に警告を表示する

## 9. 用語集

| 用語 | 説明 |
|------|------|
| ASR | Automatic Speech Recognition（自動音声認識） |
| WER | Word Error Rate（単語誤認識率） |
| OCR | Optical Character Recognition（光学文字認識） |
| セッション | 1回の録音と、その関連資料・文字起こし・ノートをまとめた単位 |
| ノート生成 | 文字起こしと資料情報から、読みやすい整理済み文書を生成する処理 |
