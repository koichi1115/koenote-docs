**バージョン**: 2.0  
**作成日**: 2026-04-19

## 1. サービス定義

### 1.1 プロダクトの本質

EchoNote は、単なる録音アプリでも、単なる文字起こしアプリでもない。  
**「話された内容を、資料文脈と根拠付きで再構成し、あとから信頼して使えるノートに変えるサービス」** である。

市場には録音、文字起こし、要約を提供するサービスは多数存在する。しかし、多くは以下の限界を持つ。

- 専門用語、固有名詞、略語、数字に弱い
- 配布資料やスライドを十分に活用できない
- 要約結果に「どこが根拠か」が残らない
- AIがそれらしくまとめても、ユーザーが信じてよいか判断しづらい
- 一度限りの要約で終わり、次回以降に知識が蓄積されない

EchoNote は、これらの弱点を以下の方針で解決する。

- 録音後の高精度処理を中心に据える
- 資料から用語辞書と文脈を抽出する
- ノートの各要点に根拠となる発話区間を紐付ける
- 不確かな箇所は自動でレビュー対象として浮かび上がらせる
- セッションを越えて用語と文脈を蓄積する

### 1.2 コア価値

EchoNote のコア価値は、次の3つで定義する。

1. **Precision**
録音後に、専門用語や固有名詞に強い高精度ノートを生成できること。

2. **Evidence**
ノートの要点が、どの発話・どの資料から導かれたかを追跡できること。

3. **Memory**
単発の要約で終わらず、次回以降のセッション精度向上に活用できること。

### 1.3 唯一無二の差別化要素

EchoNote が目指す差別化は、以下の組み合わせにある。

| 差別化要素 | 説明 |
|------------|------|
| 資料主導補正 | OCRした資料から用語・略語・固有名詞を抽出し、ASR補正に活用する |
| 根拠付きノート | ノートの各ブロックに元発話区間と引用根拠を保持する |
| 不確実性の可視化 | 信頼度が低い箇所や根拠の弱い記述をレビュー対象として提示する |
| セッション横断の用語記憶 | 同一授業、同一顧客、同一シリーズの過去用語を再利用する |
| その場の集中を守る設計 | 録音中は最小操作、価値の大半は録音後に回収する |

### 1.4 対応プラットフォーム

| フェーズ | プラットフォーム |
|----------|-----------------|
| Phase 1 | iPhone（iOS 17以上）+ Apple Watch コンパニオンApp（watchOS 10以上） |
| Phase 2 | iPad対応 |
| 将来構想 | Android / Web |

### 1.5 事業方針

- AIコストはサービス提供者が負担する
- ユーザーに外部APIキー入力を要求しない
- APIキーはサーバーサイドで管理し、クライアントへ配布しない
- Phase 1 は個人利用を中心とし、アカウント不要でも価値が成立することを優先する
- 共有・同期は Phase 3 で段階投入する

- **課題**: ノートを取ると聞き逃し、聞くと書けない

- **欲しい結果**: 決定事項、論点、Todo、根拠発言がまとまった議事メモ

## 3. Why Now / 勝ち筋

### 3.1 解くべき本質課題

- 「録る」ことより「使える形で残る」ことが重要
- 文字起こし精度だけでは差別化にならない
- AI要約だけでは信頼性不足で実務利用に耐えにくい

### 3.2 勝ち筋

EchoNote は、次の順で価値を作る。

1. 長時間録音を安定して残す
2. 高精度ASRで全文を取得する
3. 資料と過去用語を使って誤認識を補正する
4. 根拠付きノートとして再構成する
5. 不確かな箇所だけユーザーに確認させる

この流れにより、ユーザーの手作業は「全部を読み直す」から「怪しい箇所だけ確認する」へ変わる。

## 4. MVP定義

### 4.1 MVPの主価値

Phase 1 の主価値は、**録音終了後10分前後で、根拠付きの高精度ノートを得られること** とする。

### 4.2 MVPで必ず成立させる体験

- 1タップで録音開始できる
- 60分以上のセッションを取りこぼさず記録できる
- 録音終了後、自動で文字起こしと補正が進む
- 資料がある場合、用語精度が改善する
- 最終的に、読み返し可能なノートが生成される
- ノートの重要項目に、元発話への根拠が付与される
- 根拠引用をタップすると元音声の該当区間を再生できる
- 処理完了時にプッシュ通知でノート準備完了を知らせる
- 怪しい箇所だけを確認すればよい
- 過去セッションの用語が再利用された場合、その効果がわかる

### 4.3 MVP成功指標

| 指標 | 目標値 |
|------|--------|
| 録音完了率 | 97%以上 |
| 文字起こし完了率 | 95%以上 |
| ノート生成完了率 | 90%以上 |
| 補正後WER改善率（資料あり） | 補正前比 30%以上改善 |
| 根拠リンク付与率 | ノートブロックの90%以上 |
| レビュー対象抽出精度 | ユーザー修正箇所の70%以上を事前にレビュー対象化 |
| セッション後の手修正時間 | 5分以内 |
| 継続利用率 | 初回利用者の翌週継続率40%以上 |

## 5. 機能要件

### Phase 1 — Context-Aware Note Engine

---

#### 機能1：セッション録音

**ユーザーストーリー**  
> As a ユーザー,  
> I want to 最小操作で録音を開始し、最後まで保存したい,  
> So that その場では内容を聞くことに集中できる。

**受け入れ条件**
- [ ] ホーム画面から1タップで録音を開始できる
- [ ] 録音中は録音状態、経過時間、入力レベルを確認できる
- [ ] 画面オフ中でも録音を継続できる
- [ ] 録音停止後、音声ファイルをセッションとして保存できる
- [ ] 60分以上の録音データを保存できる
- [ ] 録音失敗時は失敗理由を表示し、再試行できる

**補足**
- 録音中のリアルタイム文字表示は参考機能であり、MVP成功条件には含めない

---

#### 機能1B：Apple Watch コンパニオン録音

**ユーザーストーリー**
> As a iPhone を取り出しにくい場面のユーザー（授業中・歩行中・打ち合わせ中など）,
> I want to Apple Watch から最小操作で録音を開始・停止し、ブックマークも残したい,
> So that あとで iPhone を開いたときには通常の録音セッションと同じようにノート化されている。

**受け入れ条件**
- [ ] Watch 単体で録音開始・停止できる（iPhone を操作する必要がない）
- [ ] 録音中に Watch からブックマーク（あとで振り返る目印）を追加できる
- [ ] 録音停止後、音声と所要時間とブックマークが iPhone へ自動転送される
- [ ] iPhone で EchoNote を開いたとき、Watch 録音が「録音済み」セッションとして取り込まれる
- [ ] 取り込まれたセッションは通常録音と同じパイプライン（文字起こし→補正→ノート→レビュー）で処理される
- [ ] iPhone 側がアプリを開いた状態であれば、ユーザーがセッションを個別にタップしなくても順次処理が進む（機能1Cと連動）
- [ ] 転送中・転送完了が Watch UI 上で視認できる

**補足**
- 転送は WatchConnectivity の `transferFile` を使うため、iPhone がスリープ中でも OS が後で配信する
- 一度に未配信の録音が複数あっても、iPhone を開いたタイミングで全件が取り込まれる
- Watch アプリは companion App として iPhone 本体アプリに同梱配信する（個別ダウンロード不要）

---

#### 機能1C：録音済みセッションの自動処理

**ユーザーストーリー**
> As a 取り込まれた録音をすぐにノート化したいユーザー,
> I want to アプリを開いておくだけでパイプライン処理が順次進む,
> So that Watch からまとめて流し込んだ録音や前回中断した録音を、いちいち1件ずつタップせずに片付けられる。

**受け入れ条件**
- [ ] アプリを開いた瞬間に「録音済み」状態のセッションがあれば自動でパイプラインが起動する
- [ ] 複数の録音済みセッションがある場合は1件ずつ順次処理する（並列実行しない）
- [ ] アプリがバックグラウンドから前面に復帰したときも未処理セッションがあれば再開する
- [ ] 個別セッション画面を開いていなくてもバックグラウンドで処理が進む
- [ ] エラーで失敗したセッションがあっても次のセッションへ進む（再試行は手動）

**補足**
- 並列実行しない理由：API のレート制限・端末の発熱・電池消費を抑えるため
- 「失敗」状態のセッションは自動再試行の対象外（誤動作を増やさないため、ユーザー操作で再試行）

#### 機能9c：LINE AI仲裁

**ユーザーストーリー**
> As a ユーザー,
> I want to まとめ資料をもとにAIが相手と個別に話してくれる場を設けたい,
> So that お互いが本音を言えて、感情的にならずに落としどころを見つけられる。

**概要**

まとめ資料の生成後、AIが双方と個別にLINEで会話し中立的な解決案を提示する機能。
相手はアプリのインストール不要。EchoNote公式LINEだけで参加できる。

**フロー**

```
1. まとめ資料生成後「AIに仲裁を依頼する」ボタンを押す
2. 一意の session_id と secret が発行される
3. ユーザーが session_id と secret を相手に共有する
4. 双方がそれぞれ EchoNote 公式 LINE に session_id + secret を送信する
5. LLM（まとめ資料をコンテキストに保持）が双方と個別に会話し言い分を聞く
6. 解決案がまとまったら、同一内容を双方に送信してセッション終了
```

**受け入れ条件**
- [ ] まとめ資料生成後に「AIに仲裁を依頼する」ボタンを表示できる
- [ ] session_id（公開）と secret（非公開）のペアを生成できる
- [ ] session_id + secret を相手に共有するためのシェアシートを表示できる
- [ ] LINE公式アカウントで session_id + secret を受け付けられる
- [ ] 双方がそれぞれ独立した会話スレッドでLLMと対話できる
- [ ] LLMはまとめ資料の内容をコンテキストとして保持して会話できる
- [ ] AIが解決案をドラフトし、双方に確認を求めることができる
- [ ] 双方が承認したら同一の解決サマリーを両者に送信してセッションを終了できる
- [ ] セッションに有効期限（72時間）を設定できる
- [ ] 片方のみ参加のまま期限切れになった場合、参加者に通知できる
- [ ] 送信前に「会話内容がLINEサーバーを経由する」ことへの同意確認を表示できる
- [ ] DV・ハラスメント関連キーワード検出時に相談窓口リンクを表示できる

**解決判定フロー**

```
双方との個別会話が一定の収束を示す
  → AIが解決案ドラフトを生成
  → 双方に「この内容で合意しますか？」を送信
  → 両者が承認 → 同一サマリーを送信して終了
  → 一方が否認 → 再会話フローへ
```

**制約**
- 相手がLINEを持たない場合は利用不可（代替としてSMS/メール連携を将来検討）
- セッション内の会話はサーバー側で暗号化保存、終了後に自動削除
- LINEのメッセージ課金を考慮し、1セッションあたりのターン数に上限を設ける（目安：片側20ターン）

**補足**
- 非対称プライバシー（相手に見せずに本音を言える）が感情的な場面での鍵
- 相手がアプリ不要でLINEのみで参加できる点が参入障壁を下げる
- LINE普及率93%（日本）により実質的に全ユーザーが利用可能

## 6. 非機能要件

### 6.1 パフォーマンス

| 指標 | 目標値 |
|------|--------|
| 録音開始時間 | 3秒以内 |
| 60分音声の文字起こし完了時間 | 10分以内 |
| AI補正完了時間 | 3分以内 |
| ノート生成完了時間 | 60秒以内 |
| OCR処理時間 | 1ページあたり5秒以内 |

### 6.2 品質

- 補正後テキストは「読み返せば理解できる」ではなく「そのままノート生成の入力として使える」品質を目指す
- 資料ありセッションは資料なしセッションより明確に精度改善すること
- 根拠のないノート記述を最小化すること

### 6.3 信頼性

- 処理失敗時に状態を失わない
- API失敗時でも録音データと原文は保持される
- 各処理段階の状態をユーザーが把握できる

### 6.4 セキュリティ

- 音声、OCR、文字起こし、ノートは端末内に保存する
- APIキーはサーバーサイドで管理する
- 外部送信データは処理に必要な範囲へ限定する
- 送信先をユーザーへ明示する

### 6.5 オフライン対応

- オフライン時でも録音とローカル保存は可能
- 文字起こし、補正、ノート生成は保留状態にできる
- 復帰後に自動再開できる

### 6.6 アクセシビリティ

- Dynamic Type対応
- VoiceOver対応（録音操作、ノート閲覧、レビューキュー操作）
- ダークモード対応

### 6.7 ストレージ・バッテリー

- 60分録音のストレージ使用量は50MB以下を目標とする
- 60分連続録音時のバッテリー消費は10%以下を目標とする
- 端末容量不足時は録音開始前に警告を表示する
- 古い音声ファイルの自動アーカイブ/削除ポリシーを設定で選択できる

## 11. 競合分析と差別化戦略（2026-05）

### 11.1 主要競合

| 競合 | 強み | KoeNoteとの違い |

### 11.2 KoeNoteのポジション（弱者の戦略）

Nottaや Google が「広く・汎用的に」戦う強者である以上、KoeNote は**一点突破**で戦う。

**狙うポジション：「AIノートを信頼して使える唯一のアプリ」**

- 証拠として使える（根拠リンク・音声再生）
- 専門用語に強い（資料OCR + 用語メモリ）
- 大手が手を出せない個人ユースケース（話し合いモード・ジャーナリング）

### 11.3 一点突破の候補セグメント

**保護者会・学校説明会**
- 専門用語が多い・資料が配られる・後で振り返りたい = KoeNoteのコアユースケース
- 子育て割（申告制）で入口を作り、このセグメントでNo.1を目指す
- GoogleやNottaはこのセグメントへの最適化をしていない

## 12. マネタイズ戦略（2026-05）

### 12.1 基本方針

- App Storeに無料で公開済み（審査通過後にIAP追加）
- APIコスト（約$0.58/セッション）を賄える価格設定が必要
- Apple IAP（30%手数料）を考慮した設計

### 12.2 価格モデル

| プラン | 価格 | 内容 |
|---|---|---|
| 無料 | ¥0 | 月3セッションまで・用語メモリ10件上限 |
| 個人プレミアム | ¥680〜780/月 | 無制限セッション・用語メモリ無制限・話し合いモード |
| 年額 | ¥5,800/年 | 個人プレミアムの年払い割引（約28%引き） |

### 12.3 割引施策（申告制・検証不要）

**子育て割（推奨）**
- 申告制で¥480/月
- 要件定義書のターゲット「保護者会参加者」と直結
- 子育てコミュニティは拡散力があり口コミ効果が高い
- Apple IAPでは「子育て割プラン」として別商品を作成し申告者に案内する

**県内企業割（検討中）**
- 中小企業・士業向けの地域限定キャンペーン
- 導入事例を作りやすく、BtoBへの展開起点になる可能性

### 12.4 IAPの実装方針

- StoreKit 2（iOS 15以降）を使用
- 月額サブスクリプション商品を App Store Connect に登録
- 購入状態は `Transaction.currentEntitlements` で管理
- 割引プランは別 Product ID として登録（申告者に個別案内）
- 審査済みアプリへの IAPは再審査不要で追加可能（メタデータ審査のみ）
