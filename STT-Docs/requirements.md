**バージョン**: 1.0  
**作成日**: 2026-04-18  
**ステータス**: ドラフト

---

## 1. サービス概要

### 1.1 背景・目的

学校の講義、企業セミナー、保護者会、説明会などの場では、口頭説明と配布資料が同時に存在する。従来のメモは手書きかテキスト入力が中心であり、発話に集中しながらメモを取ることは困難だった。

既存の文字起こしアプリ（Otter.ai / Notta等）はリアルタイムASRを提供するが、以下の課題が未解決のまま残っている：

- 配布資料の専門用語・固有名詞によるASR誤認識（日本語は特に顕著）
- 文字起こし後の「整理・要約・アクション化」が手動
- チームでの音声・資料・タスクの一元管理ができない

KoeNote は、**音声録音・AI補正・資料スキャン・要約生成・Todo管理・チーム共有** を一つのアプリで完結させることで、「聞くことに集中できる場」を実現する。

### 1.2 サービス名

**KoeNote（コエノート）**  
声（Koe）＋ Note（ノート）。声がそのままノートになるコンセプトを体現。

### 1.3 対応プラットフォーム

| フェーズ | プラットフォーム |
|----------|-----------------|
| MVP（Phase 1） | iOS 17以上 |
| Phase 2以降 | Android対応を検討 |

## 3. 機能要件

### Phase 1 — MVP（コア3機能）

---

#### 機能1：リアルタイム音声文字起こし

**ユーザーストーリー**  
> As a 学生・ビジネスパーソン,  
> I want to 録音ボタンを押すだけでリアルタイムに文字起こしされる,  
> So that 話を聞くことに集中できる。

**受け入れ条件**
- [ ] 録音開始ボタンを押すと即座に音声キャプチャが始まる
- [ ] 発話から2秒以内にテキストが画面に表示される
- [ ] 日本語・英語が混在する発話を認識できる
- [ ] バックグラウンド録音に対応する（画面をオフにしても継続）
- [ ] 録音中はリアルタイムで波形インジケーターが表示される
- [ ] 文字起こしテキストは自動的にローカル保存される
- [ ] 録音停止後も文字起こし結果を閲覧・コピーできる

**制約**
- オフライン（SFSpeechRecognizer）で最低限動作すること
- クラウドASR（Whisper API）はオプション設定

---

#### 機能2：AIによるASR誤認識補正

**ユーザーストーリー**  
> As a ユーザー,  
> I want to 文字起こし結果の誤認識が自動で修正される,  
> So that 専門用語や固有名詞の聞き間違いを後で訂正する手間がなくなる。

**受け入れ条件**
- [ ] 録音停止後、Claude API（Haiku 4.5）による補正が自動実行される
- [ ] 補正前/補正後を並べて確認できる（差分表示）
- [ ] ユーザーが手動で修正箇所を元に戻せる
- [ ] 補正はバックグラウンドで実行され、完了時に通知される
- [ ] API未接続（オフライン）時は補正なしでスキップされる

**制約**
- 補正処理は録音停止から60秒以内に完了すること
- Claude API のプロンプトキャッシュを活用してコストを削減

---

#### 機能3：ドキュメントスキャン → 文字起こし精度向上

**ユーザーストーリー**  
> As a ユーザー,  
> I want to 手元の配布資料をスマホでスキャンしてセッションに紐付ける,  
> So that 資料に含まれる専門用語・固有名詞が文字起こしに正しく反映される。

**受け入れ条件**
- [ ] セッション開始前または開始後にドキュメントスキャンを起動できる
- [ ] 複数ページ（最大20ページ）のスキャンに対応する
- [ ] スキャン済みドキュメントのOCR結果をセッションに紐付けられる
- [ ] AI補正プロンプトに資料のテキストがコンテキストとして自動注入される
- [ ] スキャンした資料の画像とOCRテキストは端末にローカル保存される
- [ ] スキャン済み資料の一覧を確認・削除できる

---

### Phase 2 — 要約・Todo

---

#### 機能4：要約資料の自動生成

**ユーザーストーリー**  
> As a ユーザー,  
> I want to 録音停止後に自動で要約資料が生成される,  
> So that セミナー・講義の内容を後から簡単に振り返れる。

**受け入れ条件**
- [ ] 録音停止後に「要約生成」ボタンが表示される
- [ ] 生成する資料のテンプレートを選択できる（議事録 / 学習ノート / アクションリスト）
- [ ] 生成完了後、資料をMarkdown形式で確認・編集できる
- [ ] PDF / テキストファイルとしてエクスポートできる
- [ ] 生成には元の文字起こし＋スキャン資料が両方使われる

---

#### 機能5：Todo自動抽出＋元資料リンク

**ユーザーストーリー**  
> As a ユーザー,  
> I want to 要約から自動でTodoが抽出される,  
> So that 聞いた内容からのアクションを確実に実行できる。

**受け入れ条件**
- [ ] 要約生成後にTodoリストが自動表示される
- [ ] 各TodoにはセッションIDと文字起こし内の参照箇所リンクが付く
- [ ] ユーザーがTodoを追加・編集・削除・完了マークできる
- [ ] Todoは期日設定が可能
- [ ] iOSリマインダーへのエクスポートに対応する

---

### Phase 3 — チーム共有

---

#### 機能6：チーム招待・プロジェクト共有

**ユーザーストーリー**  
> As a プロジェクトオーナー,  
> I want to チームメンバーをプロジェクトに招待する,  
> So that 全員が同じ音声・資料・Todoを確認・分担できる。

**受け入れ条件**
- [ ] メールアドレスでユーザーを招待できる
- [ ] 招待されたユーザーは音声の再生・文字起こし閲覧・資料閲覧・Todo閲覧ができる
- [ ] Todoの担当者（Assignee）をチームメンバーから指定できる
- [ ] オーナーは閲覧権限/編集権限を設定できる
- [ ] プロジェクトへの招待メール通知が送信される
- [ ] チームメンバーはTodoのステータス更新ができる

## 4. 非機能要件

### 4.1 パフォーマンス

| 指標 | 目標値 |
|------|--------|
| 文字起こし遅延（SFSpeechRecognizer） | 発話から2秒以内 |
| AI補正完了時間（Claude API） | 録音停止から60秒以内 |
| ドキュメントスキャン・OCR処理時間 | 1ページあたり3秒以内 |
| 要約生成時間（Claude API） | 60分の音声で2分以内 |
| アプリ起動時間 | コールドスタートで3秒以内 |

### 4.2 セキュリティ・プライバシー

- 音声データは端末内に暗号化して保存（AES-256）
- クラウドへの音声送信はユーザーの明示的な同意が必要
- Claude API送信前に個人情報のマスキング処理（オプション）
- Firebase Auth によるユーザー認証（メール/Google/Apple Sign In）
- プロジェクト共有データはFirestoreのセキュリティルールで保護

### 4.3 可用性・オフライン対応

- 基本機能（録音・SFSpeechRecognizer文字起こし）はオフラインで動作
- AI補正・要約生成はネットワーク必須（オフライン時はスキップ）
- セッション履歴・Todoはローカルキャッシュでオフライン閲覧可能

### 4.4 アクセシビリティ

- Dynamic Type対応（文字サイズ変更）
- VoiceOver対応
- ダークモード対応

### 4.5 対応デバイス

- iPhone（iOS 17.0以上）
- iPad対応（Phase 2）

## 7. 用語集

| 用語 | 説明 |
|------|------|
| ASR | Automatic Speech Recognition（自動音声認識） |
| WER | Word Error Rate（単語誤認識率）。低いほど精度が高い |
| OCR | Optical Character Recognition（光学文字認識） |
| セッション | 1回の録音から生成されるひとまとまりのデータ単位 |
| SFSpeechRecognizer | Appleの音声認識フレームワーク（オンデバイス対応） |
| VisionKit | Appleのドキュメントスキャン・OCRフレームワーク |
